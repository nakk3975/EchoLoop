# EchoLoop

30초의 행동을 기록하고 과거의 나와 협력하는 브라우저 퍼즐 게임입니다. `03_EchoLoop_WebGame_Plan_v2_KO(1).pdf`의 초기 플레이·제작 범위를 구현했습니다.

## 실행

Node.js 22.18 이상을 사용합니다.

```sh
npm ci
npm run check
npm start
```

개발 화면: `npm run dev` (Vite). 배포 환경은 Node 서버가 `dist`와 API를 같은 출처에서 제공합니다.

## 구현한 기능

- 10Hz 결정론적 엔진, 300tick 반복, 과거 기록 최대 3개
- 현재는 tick 시작의 문 상태로 이동, 이동 후 발판·OR/AND 문 갱신
- 고정 좌표 과거 재생, 마지막 위치 대기, 기록 삭제 시 뒤 체인 삭제
- 20개 챕터 × 5개 = 100개 고정 레벨. 기존 튜토리얼 5개 및 대표 퍼즐(3/8/11tick 해답) 유지
- 6~20번은 9×7~11×7의 수작업 소형 퍼즐: 공명(2/3명 중첩), 기억 스위치(재진입 시 반전), 반전 문을 시간차 기록과 조합
- 기존 ID fracture-21~30은 9×7~13×9의 수작업 소형 퍼즐: 엇갈린 박동·과거의 이탈·현재 전용 발판·원격 반전 후, 포털별 역할 선택·왕복·신호 전달·합류를 조합
- 변경 전 맵의 저장 기록은 보존하고 새 퍼즐 재시작 안내 제공
- 잔상 전용 / 현재 전용 발판, 주기적으로 열리는 박동 문, 연결 포털, 방향 통로
- 후반 3개 기록의 연쇄 협력, 기존 46~50번 최대 25×23 미궁. 50번 해답 최종 반복 222tick
- 보라색 시간 균열 세계, 금빛 실체 여행자와 번호별 유령 캐릭터, 챕터별 별자리 선택
- 신규 기믹을 제작실에서 배치·연결·테스트하고 지도 확대 가능
- 한 수 되돌리기(Z): 문·충전·스위치·조각까지 재생으로 복원, 반복 시작점에서는 마지막 기록 확정 취소
- 현재 반복 재시작(과거 유지) / 레벨 처음부터(확인 후 모든 기록 초기화)
- 기존 ID fracture-51~80: 11×9~15×9 소형 방, 충전 발판·단독 발판·현재 전용 조각 수집 도입 후 기존 기믹과 조합. 후반에는 삼중 공명과 수집 방 ON/출구 OFF 조건 결합
- 일시정지, 탭 이탈 정지, 프레임 중단 감지, 키보드·화면 방향 버튼
- IndexedDB 진행 저장, 재생 검증 후 이어하기, JSON 가져오기·내보내기
- 격자 제작기, 문 연결, OR/AND, 100단계 실행 취소·다시 실행, 확대
- 초안 저장, 내 맵 목록, 독립 테스트, 클리어 해답 재생 검증·내보내기
- 서버의 동일 엔진을 이용한 해답 검증 API
- 아이디·비밀번호 가입/로그인, 계정 진행 저장·불러오기와 기기 간 이어하기
- 완료한 레벨·현재 위치·과거 기록 계정 자동 저장(5초 주기), 다른 기기의 변경 충돌 감지
- Neon 연결 시 기존 브라우저별 온라인 백업과 복구, 낙관적 잠금, 중복 요청 검사

## 계정으로 이어하기

1. `로그인 / 가입` → `계정 만들기`에서 아이디와 비밀번호만 입력합니다. 이메일·휴대폰 인증이 없습니다.
2. 가입 시 현재 비회원 진행을 가져옵니다. `진행 저장`을 누르면 완료 레벨과 플레이 중인 실험의 위치·시간·과거 기록이 계정에 저장됩니다.
3. 다른 기기에서 같은 계정으로 로그인하면 계정 기록을 불러옵니다. `이어하기`를 누르세요.

로그인 상태에서 변경된 진행은 5초마다 자동 저장됩니다. 기기를 바꾸기 직전에 `진행 저장` 완료를 확인하세요. `불러오기`는 최신 계정 기록으로 이 기기의 진행을 교체합니다. 다른 기기의 저장을 발견하면 자동 저장을 중단하고, 불러오기 또는 확인 후 덮어쓰기를 선택하게 합니다. 응답 유실·서버 오류도 성공으로 표시하지 않습니다.

비회원도 플레이하고 브라우저에서 이어 할 수 있습니다. 비회원 기록과 각 계정의 로컬 기록은 분리되며 로그아웃하면 원래 비회원 기록으로 돌아갑니다. 계정 저장에는 제작실의 초안·설정은 포함하지 않습니다. 별도 인증 정보를 받지 않으므로 비밀번호 찾기는 지원하지 않습니다. 비밀번호는 scrypt 해시로, 로그인 세션은 해시된 무작위 토큰과 HttpOnly/SameSite 쿠키로 관리합니다. 운영 쿠키에는 Secure를 설정합니다.

`DATABASE_URL`이 기존 Neon DB를 가리키면 앱 시작 시 계정/세션/진행 테이블을 추가로 준비합니다. `GET /api/status`의 `accounts: true`로 초기화 여부를 확인합니다. DB 연결이 없으면 가입·로그인·계정 저장은 503을 반환하고 비회원 플레이를 유지합니다.

## 조작

| 입력 | 동작 |
|---|---|
| 방향키 / WASD | 이동, 멈춘 상태에서 시간 시작 |
| Enter | 기록 확정. 마지막 위치에서 과거가 대기 |
| Z | 한 수 되돌리기. 재시작 직후에는 직전 상태 복구. 반복 시작점에서는 마지막 기록 확정 취소 |
| R | 현재 반복만 재시작 |
| Esc / Space | 일시정지·재개. Esc는 도움말·설정·삭제 확인 닫기에도 사용 |

발판에 도착한 tick의 끝에 문이 열립니다. 현재는 다음 tick부터 진입할 수 있습니다. 과거의 경로는 현재 문 상태에 영향을 받지 않습니다. 출구에 현재 캐릭터가 도착해야 승리합니다.

## 배포

`render.yaml`에 Singapore / Free 서비스가 정의되어 있습니다. 빌드는 `npm ci && npm run check`, 시작은 `npm start`, 헬스체크는 `/health/live`입니다.

Neon 신규 전용 프로젝트의 pooled connection URL을 Render의 `DATABASE_URL` 비밀 환경변수로 설정합니다. URL을 Git에 넣지 않습니다. 앱 시작 시 `db/001_device_backup.sql`과 같은 전용 스키마를 준비합니다. DB 연결 실패 시 로컬 게임은 정상 제공하며 온라인 저장 성공으로 표시하지 않습니다.

`GET /api/status`의 `database: true`는 시작 시 DB 준비 성공 여부입니다. DB 연결 상태를 지속적으로 검사하는 신호가 아닙니다.

## 범위와 제한

- 이번 릴리스는 E0~E3 중심의 개인 플레이 베타입니다. OAuth 계정, 비공개 초대, 공개 커뮤니티 목록, 불변 발행 버전, 신고·운영 기능(E4/E5 전체)은 미구현입니다.
- 기획서의 공통 Java API 제안 대신 독립 Node.js/TypeScript API를 사용하여 브라우저와 서버가 같은 퍼즐 엔진을 사용합니다. 렌더링은 Phaser 대신 SVG이며 판정과 분리되어 있습니다.
- 온라인 백업은 이 브라우저의 무작위 256비트 키로 보호합니다. 기존 브라우저 백업 기능입니다. 기기 간 이어하기는 별도의 계정 저장을 이용하세요. 사이트 데이터 삭제 시 키를 잃으므로 JSON 내보내기를 사용하세요.
- 브라우저 저장도 영구 백업이 아닙니다. 최초 접속에 인터넷이 필요하고 오프라인 재접속을 보장하지 않습니다.
- Render 무료 절전 후 첫 요청 대기 및 실제 사용자 난이도는 별도 운영 검증이 필요합니다.
- 기본 키 배치 변경, 드래그 페인팅, 성능 목표의 실제 기기 검증은 후속 작업입니다.

## API

- `GET /health/live` / `GET /api/status`
- `GET /api/catalog`
- `POST /api/verify` — `{stage, solution}` 재생 성공 시 `SERVER_REPLAY_VERIFIED`
- `GET /api/backup` / `PUT /api/backup` — 브라우저 백업 키 필수. DB 미연결 시 503

- `POST /api/account/register` / `POST /api/account/login` — `{username,password}`
- `GET /api/account/session` / `POST /api/account/logout` — HttpOnly 세션 쿠키
- `GET /api/account/progress` / `PUT /api/account/progress` — 계정별 리비전 기반 진행 기록. PUT은 `{baseRevision,payload:{version:1,current,completed}}`; 변경 요청에 `X-Requested-With: EchoLoop` 필요

## 캠페인 구성과 검증

`src/campaign-data.ts`는 재현 가능한 설계 규칙과 시드로 만든 45개 추가 고정 맵입니다. 플레이할 때마다 무작위로 바뀌지 않습니다. 각 구역의 미로, 필수 장치, 잔상 역할을 구성하고 실제 엔진 탐색으로 해답을 계산했습니다. `node --experimental-strip-types scripts/build-campaign.ts`로 재생성합니다.

100개 모두 기록 체인과 최종 해답을 재생 검증합니다. 자동 검증은 해결 가능성을 보장하며, 난이도는 장치 조합·기록 역할·상태 전환·타이밍에 따라 분류했습니다. 실제 사람의 체감 난이도/최단 해답은 별도 검증 대상입니다.

신규 장치는 선택 필드로 추가하여 기존 엔진 1 저장 형식을 유지합니다. 확장 이전 저장 fixture를 새 엔진에서 복원하는 회귀 검사를 포함합니다.

### 2026-10-07 박동하는 시간·공간의 접힘 재설계

21~30번의 긴 생성 미로를 `src/rhythm-fold-stages.ts`의 작은 방 10개로 대체합니다. 21~25번은 안전한 방에서 다음 박자를 기다리기 → 과거의 이탈 → 과거와 현재 전용 발판의 분담 → 두 기록의 ON/OFF → 원격 스위치 지휘로 진행합니다. 26~30번은 기록과 현재의 포털 선택 → 돌아온 기록과 합류 → 두 고립된 방 사이의 신호 전달 → 세 포털의 역할 분담 → 왕복·공명·이탈·박동의 조합으로 진행합니다. 기존 레벨 ID와 완료 목록, 이전 맵의 저장은 유지합니다.

`node --experimental-strip-types scripts/solve-rhythm-fold.ts`는 실제 이동을 먼저 최소화하고, 같은 이동 수에서는 시간을 줄이는 경로로 해답을 재생성합니다. 기다리는 동안 불필요하게 왕복해서 이동 한도를 늘리지 않습니다. 이어서 `node --experimental-strip-types scripts/build-move-limits.ts`로 검증된 전체 기록과 현재 이동 +4회의 한도를 다시 계산합니다. 최종 문 뒤에 안전하게 움직일 공간을 두어 왕복 실수 두 번에 대한 회귀 검사도 유지합니다.

`tests/rhythm-fold.test.ts`는 10개의 크기·해답·최종 40tick 이하 진행, 막힌 입력 없는 공략, 박동 대기를 생략한 실패, 잔상이 영구히 남으면 막히는 반전 문, 모든 포털 쌍의 필수 역할, 이전 맵 저장 복원을 검사합니다. 변경 전후 크기와 공략 비용은 `artifacts/chapter-redesign.json`에 기록합니다. 전체 100개는 키보드 및 화면 방향 버튼으로 Chromium에서 순차 진행합니다.

## 에셋

격자·캐릭터·장치·아이콘은 자체 SVG/CSS입니다. 외부 게임 에셋이나 유료 AI API를 사용하지 않습니다. Google Fonts의 Noto Sans KR / Space Grotesk를 사용하며 네트워크 불가 시 시스템 폰트로 표시합니다.

### 전체 화면 흐름 회귀 검사

`npm run test:campaign-ui`는 프로덕션 React 번들을 JSDOM에서 실행하고 실제 키 이벤트와 제어된 프레임으로 1~100번을 순서대로 풉니다. 모든 기록 확정, 클리어 결과창의 기본 포커스, 다음 실험, 챕터 경계, 마지막 실험의 목록 복귀 및 완료 기록 100개 저장을 확인합니다. 10레벨마다 새로고침 복구와 클리어 직후 되돌리기 후 재클리어도 검사합니다. 결과는 `artifacts/campaign-ui.json`에 기록합니다.

이는 DOM 통합 검사이며 실제 브라우저의 렌더링·입력 지연·모바일 레이아웃 검사와 구분합니다. 2026-10-01 검사에서 전체 80개와 기존 엔진/API 테스트 45개가 통과했고, 배포 브라우저에서는 검증된 저장 파일 복구 후 결과창 Enter가 다음 실험으로 이동하는 것을 별도로 확인했습니다. 새 진행 차단 오류는 발견되지 않았습니다.

### 비공개 플레이 버전과 2026-10-06 입력 개선

첫 화면에서 100레벨 선택·시작·이어하기를 바로 제공합니다. 결과창 Enter는 되돌리기 포커스에서도 다음 실험으로 진행하고 길게 누른 Enter는 무시합니다. 도움말·설정 등 열린 대화상자는 게임 입력을 막습니다.

`npm run test:campaign-ui`는 모든 결과창을 Enter로 통과하는 회귀 검사를 포함합니다. 실제 Chromium으로 프로덕션 화면을 검사하려면 빌드 후 개발 서버의 `/qa.html`에서 전체 검증을 실행합니다. QA 저장은 별도 DB를 사용하며 배포된 게임에는 검사 화면을 포함하지 않습니다.

`.openai/hosting.json`이 있는 정적 비공개 빌드에서는 서버 백업 버튼을 숨깁니다. 기존 Render/Neon 서버 빌드는 온라인 백업을 유지합니다.

### 2026-10-06 편의성 개선

- 반복 재시작과 전체 초기화 직후, 진행을 다시 시작하기 전에 `재시작 취소` 또는 Z로 직전 시간·위치·과거를 복구합니다. 초기화 확인을 취소해도 시간은 멈춥니다.
- 홈의 이어하기 안내에 실험 이름·남은 시간·과거 수를 표시합니다. 저장된 실험의 챕터를 열고 해당 카드를 눌러 정확한 진행으로 이어갑니다. 완료된 저장은 다음 미완료 실험을 안내합니다.
- 모바일의 지도 위에 도움말·설정·확대를 둡니다. 도움말·설정·힌트·확대 시 일시정지하고, 닫은 대화상자의 포커스는 게임으로 돌아옵니다. Ctrl/Cmd/Alt 조합의 브라우저 단축키를 가로채지 않습니다.
- 확대하면 현재 캐릭터가 보이도록 지도를 이동합니다. 작은 화면에서는 제목의 줄바꿈·큰 글씨·방향 패드의 실제 높이를 측정해 지도가 조작 영역과 겹치지 않게 맞춥니다.

`npm run check`에 14개 입력 검사와 12개 편의성 흐름 검사를 포함합니다. `npm run test:ux-ui`로 복구·Esc·포커스·저장된 챕터·손상된 저장 처리를 따로 확인할 수 있습니다. 개발 서버 `/qa.html?touch=1`의 `편의 기능·화면 검사`는 320×568, 390×680, 740×390, 큰 글씨, PC 980×800·1366×900에서 작은 맵·기존 fracture-50·도약 맵의 조작 영역과 확대를 검사합니다. QA 화면은 배포 번들에 포함하지 않습니다. 자동 검증은 실제 휴대폰 하드웨어에서의 체감과 별개입니다.

시작·일시정지 안내와 버튼을 한 묶음으로 가운데 정렬하고 양쪽 안쪽 여백을 맞춥니다. 모바일의 시간·반복·과거 수와 지도 도구는 균등한 열로 정렬하며, 설명 문단에는 읽기 쉬운 너비와 줄 간격을 둡니다. PC에서는 지도를 기존의 넉넉한 표시 높이와 배율로 복구하고, 큰 지도는 확대로 탐색합니다. 고정 조작 영역 위에 맞추는 높이 제한은 모바일에만 적용합니다. 위 화면 검사는 안내 문구의 줄바꿈 전후 중앙 정렬·세로 정렬·영역 내 배치, 모바일 도구의 동일한 폭, PC 조작 버튼의 중앙 정렬, PC 지도·타일의 원래 배율을 함께 확인합니다.

### 2026-10-07 문 앞 입력과 이동 한도

- 문·벽·방향 통로에 막힌 순간 누르고 있던 방향 입력을 해제합니다. 문이 열려도 자동으로 뛰어나가지 않으며, 손을 떼고 다시 누르면 이동합니다. 대기 중에도 시간과 과거 기록은 계속 진행됩니다.
- 캠페인 100개에 검증된 전체 공략의 실제 이동 +4회 한도를 적용합니다. 과거로 확정한 기록과 현재 이동을 합산하고, 대기·막힌 입력·과거의 재생은 추가 차감하지 않습니다. 포털 이동은 한 번으로 셉니다.
- 남은 이동을 시간·반복·과거 수와 함께 표시합니다. 한도가 끝나면 시간을 멈추고 결과창에서 Z로 되돌리거나 R로 반복을 재시작합니다. 되돌리기는 횟수도 환불하며, 반복 재시작은 현재 반복의 이동만 환불합니다. 마지막 허용 이동으로 출구에 도착하면 성공입니다.
- 이전 저장은 먼저 기존 체크섬으로 검증합니다. 같은 맵에서 새 한도를 적용할 수 있는 기록은 위치·시간·과거 경로를 보존해 이어갑니다. 이미 한도를 넘긴 기록이나 이전 맵은 원래 규칙으로 복구하고 새 규칙으로 시작하는 버튼을 제공합니다. 제작실의 기존 무제한 맵도 유지합니다.

`tests/move-budget.test.ts`는 100레벨 모두 실제 왕복 실수 두 번(+4회) 후 성공하고 세 번째 실수 시 이동 한도가 소진되는 경로를 재생합니다. 결과는 `artifacts/movement-budgets.json`에 남깁니다. 입력 검사는 키보드·터치로 닫힌 문 앞에서 계속 누르다가 과거가 문을 열어도 이동하지 않는지 확인합니다. 편의성 검사는 이동 소진 결과창의 포커스·Z·재시작 복구·마지막 이동 성공·다음 레벨 초기화를 포함합니다.


## 다섯 기믹과 난이도 순서 (2026-10-07)

시간 상자(현재만 밀고 일반 무게 발판 유지), 붕괴 바닥(현재가 떠나면 붕괴·과거는 무시), 역재생 잔상(기록 끝에서 출발), 잔상 도약(반복당 1회·과거 선택 1~3과 J 또는 모바일 버튼), 번호별 재생 정지(현재가 장치 위에 서 있는 동안 해당 과거만 멈춤)를 추가했습니다. 되돌리기·재시작·저장·맵 제작실에서도 같은 규칙을 사용합니다. 기존 필드가 없는 맵의 상태와 체크섬은 그대로입니다.

`src/new-mechanic-stages.ts`에는 각 기믹의 입문·응용 3개와 복합 퍼즐 5개, 총 20개 소형 맵(10×7~12×7)이 있습니다. 마지막 `confluence-05`는 다섯 기믹과 박동 문을 함께 사용합니다. 무너진 조각 방은 걸어서 나올 수 없어 도약이 필요하고, 짧게 머무는 과거를 정지해 세계 시계의 다음 박동을 기다립니다. 해답 생성기는 상자 위치, 구멍, 조각, 충전, 도약 사용과 잔상별 시계를 상태에 포함합니다.

전체 100개는 원래 튜토리얼 5개를 먼저 제공한 뒤, `src/campaign-difficulty.ts`의 기록 역할·조건 전환·타이밍·기믹 조합 순위로 정렬합니다. 맵과 해답을 ID로 함께 재배치하며 ID·완료 기록·저장된 맵은 바꾸지 않습니다. 카드의 초급/중급/고급/최상급 표시는 설계 기준이며 사람의 체감 난이도 측정치는 아닙니다. 현재 번호와 과거 ID는 다릅니다. `artifacts/campaign-order.json`이 새 번호 대응표입니다.
